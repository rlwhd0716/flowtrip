# 자동 분할 구현 실험 이력 — 종료

현재 제품 코드는 자동 창 배치 실험을 제거했습니다. [현재 화면 구성](SCREEN_CLEANUP.md)을 참고하세요.

## 1차: 내비 인접 실행 요청

공개 NEW_TASK | LAUNCH_ADJACENT 플래그로 내비 런처를 실행하고 경로를 요청했습니다. 설치 앱의 AVD 재현에서 플래그 전달은 확인됐지만 내비가 전체 앱 영역을 덮고 FlowTrip이 숨겨졌습니다. [실패 분석](AUTO_SPLIT_FAILURE_ANALYSIS.md)에 실제 bounds/표시 상태가 기록돼 있습니다.

## 2차: 자신의 창 크기 전환 요청

내비 런처 실행을 제거하고 FlowTrip 자신의 runtime portrait 요청, 실제 WindowMetrics 크기 변화와 가시 상태 관측, Activity 재생성을 넘는 비동기 대기를 구현했습니다. 창 축소 확인 전에는 경로를 보내지 않도록 했습니다. 이 방식도 두 앱의 실제 동시 표시나 1:1 비율을 보장할 공개 창 배치 진입점은 아니었습니다. 빌드·실기 검증은 사용자에게 위임했습니다.

## 현재 결정

자동 1:1 배치를 확정할 지원 근거가 없어 사용자의 조건부 요청에 따라 실험을 종료했습니다. NavigationWindowController/Session, 창 준비 콜백, 방향 요청/8초 대기와 분할 설명 UI를 제거했습니다. 추천·코스·SDK 경로 기능은 유지하고 화면을 정리했습니다.

고정 portrait, 추가 task 플래그, 숨겨진 API, 시스템 권한/오버레이로 우회하지 않았습니다. 다시 추진하려면 Pleos가 일반 앱에 허용하는 공식 자동 배치 지원 여부가 먼저 확인돼야 합니다.
