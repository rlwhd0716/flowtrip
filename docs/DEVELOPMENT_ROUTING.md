# 개발용 추천 카드의 실제 길안내 연결

## 구현 내용

사용자 요청에 따라 가상의 식당·야경·카페 카드는 그대로 두고, 그 카드의 길안내 대상만 기존 공식 SDK 샘플 목적지로 교체했다. 해당 식당의 실제 주소를 검색하거나 시연 좌표를 실제 POI로 위장하지 않는다.

- 적용 범위: Pleos SDK를 사용하는 **Debug 빌드** (`BuildConfig.DEBUG && PLEOS_SDK_ENABLED`).
- `MockRecommendationRepository`가 기존 `NavigationTestCatalog`를 주입받아 실제 테스트 목적지 전체 정보를 사용한다.
- 표시용 Place ID/이름/설명/체류/비용/추천 이유와 방문 단계는 유지한다.
- 목적지 Destination은 샘플의 실제 이름·좌표·주소·POI ID/sub-ID/provider/source를 그대로 사용한다.
- Mock 개발 빌드와 새 Release 추천 데이터는 기존 가상 목적지를 유지한다.
- 카드에 `개발용 길안내: 소프트웨어드림센터`처럼 실제 전송할 장소를 한 줄로 표시한다. 상세 주소도 개발용 목적지 주소로 구분한다. 새 패널/카드는 추가하지 않는다.
- 기존 저장 상태에 Mock 목적지가 있으면 후보를 다시 불러와 새 연결을 반영한다. 단계/후보 인덱스/방문 ID는 유지하고 복원만으로 목적지를 자동 전송하지 않는다.
- Release/Mock으로 빌드를 바꾸면 저장된 개발용 샘플 목적지 후보도 다시 불러와 해당 빌드의 목적지로 되돌린다.

## 기본 연결 순서

| 단계 | 첫 후보 | 둘째 후보 | 셋째 후보 |
| --- | --- | --- | --- |
| 식당 | 소프트웨어드림센터 | 42dot | 소프트웨어드림센터 |
| 야경 | 42dot | 소프트웨어드림센터 | 42dot |
| 카페 | 소프트웨어드림센터 | 42dot | 소프트웨어드림센터 |

현재 확인된 샘플은 두 곳이므로 3개 후보 사이에 목적지가 반복된다. 카드의 후보 수를 줄이거나 가짜 세 번째 POI를 만들지 않았다. 소프트웨어드림센터는 이전 AVD에서 SDK 안내 성공을 확인한 샘플이라 첫 대상으로 우선한다. 42dot은 목적지 대조 시간 초과 이력이 있어 성공을 보장하지 않는다.

## 버튼 동작

`이 장소로 길안내`는 별도 테스트 패널을 펼칠 필요 없이 해당 카드에 연결된 실제 목적지를 요청한다. `다음 추천 경로`/`다음 코스`도 동일하게 실제 목적지로 요청하며 SDK 성공 확인 후에만 후보/단계를 확정한다. 재시도·중복 방지·도착 이벤트 처리와 주행 UX 제한은 유지한다.

`남은 코스 경유 안내`도 카드에 연결된 실제 목적지를 사용한다. 샘플이 두 곳이라 세 단계 경로에 같은 목적지가 반복될 수 있다. 해당 조합의 경유 지원 여부/SDK 성공은 확인이 필요하며 실패를 가짜 성공으로 처리하지 않는다.

자동 화면 분할/다른 앱 강제 실행/차량 GPS 이동/가상 주행 애니메이션은 추가하지 않았다. 이 변경은 **실제 테스트 목적지로 경로 안내를 요청하는 기능**이다. 차량이 실제로 움직이거나 주행 시뮬레이션이 자동 시작된다고 표시하지 않는다.

## 변경 파일

- MockRecommendationRepository.kt: Debug Pleos 후보 목적지 연결.
- RecommendationViewModel.kt: 기존 Mock 목적지 저장 후보를 새 데이터로 갱신.
- RecommendationScreen.kt: 실제 개발용 목적지 이름/주소 구분 표시. 실제 Destination이 있으므로 기존 길안내 버튼의 Mock 차단 조건을 통과한다.
- README.md, PROGRESS.md: 현재 개발 동작 기록.

## 사용자 확인

이번 수정의 빌드/테스트/설치/실행은 수행하지 않았다.

- [ ] Pleos Debug 빌드 후 기존 후보가 개발용 실제 목적지로 갱신되는지.
- [ ] 첫 식당 카드에서 별도 패널 없이 길안내가 활성화되고 소프트웨어드림센터로 SDK 요청되는지.
- [ ] 다음 후보/다음 단계가 표의 실제 목적지를 요청하고 SDK 성공 후에만 카드가 바뀌는지.
- [ ] 내비에 표시되는 이름/주소가 식당명이 아닌 카드에 명시된 실제 테스트 목적지인지.
- [ ] 실패/중복 클릭/재시도 및 경유 안내(반복 목적지 포함) 동작.
- [ ] 회전/복귀/프로세스 복원 시 단계/후보/방문 기록이 유지되고 자동 재전송하지 않는지.
- [ ] Mock 빌드의 기존 추천 시뮬레이션, Release 빌드의 비적용 상태.

일반 추천의 실제 장소 공급자 연결 및 자동 분할 지원은 별도 과제로 남는다.
