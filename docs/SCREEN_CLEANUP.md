# 화면 정리 및 자동 배치 실험 종료

## 현재 결정

사용자 요청: 자동 반반 배치가 공식적으로 가능하면 구현하고, 불가능하면 불필요하게 늘어난 화면을 정리한다.

현재 NaviHelper 3.0.5와 일반 앱 권한 범위에서 두 앱을 자동으로 1:1 배치하고 그 비율을 고정할 공개 진입점을 확인하지 못했다. 기존 인접 실행 방식은 실제 AVD에서 실패했고, 자신의 화면 방향 요청도 두 앱 동시 표시/비율 제어를 보장하지 않는다. 모든 Pleos 버전에서 절대 불가능하다고 단정하는 대신, **현재 지원 근거가 없는 자동 배치 실험을 제품 코드에서 제거**한다.

[Pleos Window Policy](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/window)는 창 배치/크기 변경을 시스템 창 바와 제스처로 설명하고 App-to-App 실행은 기존 앱을 덮을 수 있다고 명시한다. Connect-S와 Connect-W의 비율 정책도 다르므로 일반 앱에서 임의로 반반 비율을 지정하지 않는다.

## 기본 화면에 남긴 것

- 홈: 여행 모드와 데이트 모드 진입. 자동 분할/창 크기 안내 제거.
- 추천: 현재 코스 단계, 추천 후보 번호, 장소 이름/설명/체류 시간/예산을 하나의 카드로 표시.
- 주요 조작: 이 장소로 길안내, 다음 추천 경로, 다음 코스/코스 완료, 단계 건너뛰기.
- 필요한 상태만 즉시 표시: 요청 중/실패/재시도, 현재 목적지, 도착 신호, 연결 오류. 시연 장소의 실제 안내 불가 표시는 짧게 유지.

## 기본 접힘으로 정리한 것

- 상세 정보 보기: 주소/주차/추천 이유/남은 코스/경유 안내. 넓은 창에서도 별도 여러 카드/두 열로 늘리지 않는다.
- 연결 정보 보기: 내비 SDK 상세 메시지, 경유지, 경로 상태, 위치 상태, 근접 안내.
- 실제 장소 길안내 테스트: 기존 공식 샘플 2곳과 경유 요청. 추천 화면 하단으로 이동하고 기본 접힘으로 변경. 접은 상태에서도 진행/결과/재시도를 볼 수 있다.
- 테스트 경로 오류와 일반 추천 오류를 중복 표시하지 않는다. 샘플 목적지 변경을 현재 시연 추천과 다르다고 중복 경고하지 않는다.

기존 기능은 숨기거나 접어서 접근하도록 조정했으며 샘플 목적지/경유/재시도 자체를 제거하지 않았다. 폼/데이트 설정/추천 후보와 코스 생성 로직, Hilt/Repository/SDK 결과 대조, UX 제한, 저장 상태는 유지한다.

## 제거한 자동 배치 코드

- NavigationWindowController 및 NavigationWindowSession 삭제.
- Activity의 창 관측/방향 요청/명령 수집/재생성 대기 연결 제거.
- NavHost → RecommendationViewModel → RequestNavigationUseCase의 창 준비 콜백 제거.
- portrait 요청, 8초 크기 대기, 크기 변화 조건을 경로 요청의 선행 조건으로 사용하지 않는다.
- PleosWindowGuide 삭제. 홈/추천 화면의 분할 안내 및 창 전환 메시지 UI 제거.

현재 길안내는 기존 SDK 경로 요청만 수행한다. 일반 UI에서 내비 런처/분할 Intent/Foreground 요청을 호출하지 않는다. NaviHelper 자체가 어떤 화면 전환을 수행하는지는 플랫폼 동작에 종속된다. 다른 앱의 크기/위치/방향을 제어하지 않는다.

## 수정 파일

- MainActivity.kt, FlowTripNavHost.kt: 자동 창 준비 연결 제거.
- RequestNavigationUseCase.kt, RecommendationViewModel.kt: 창 준비 콜백 제거, SDK 경로 처리 유지.
- HomeScreen.kt: 분할 설명 제거.
- RecommendationScreen.kt: 장소 카드 하나와 주요 버튼, 접히는 상세 영역.
- PlatformStatusCard.kt: 상시 큰 진단 카드 대신 필요한 요약과 접히는 연결 정보.
- NavigationTestPanel.kt: 하단 기본 접힘, 진행/결과/재시도 유지.
- NavigationWindowController.kt, PleosWindowGuide.kt: 실험 구현 삭제.
- README/진행도/기존 자동 분할 문서: 현 결정과 과거 기록 구분.

파일 경로는 app/src/main/java/com/github/flowtrip 아래 기존 패키지 경로를 따른다.

## 사용자 확인 항목

이번 정리의 빌드·Lint·단위/계측 테스트·설치·실행은 수행하지 않았다. 기존 ‘검증은 사용자 수행’ 요청을 유지한다.

- [ ] Gradle Sync/SDK 빌드, Mock 빌드 및 Compose Preview 컴파일.
- [ ] 홈에 여행/데이트 진입만 남고 추천 기본 화면이 단순해졌는지.
- [ ] 상세 정보/연결 정보/실제 장소 테스트가 기본 접힘이며 회전/재생성 후 접힘 상태가 유지되는지.
- [ ] 다음 후보/다음 코스/건너뛰기/코스 완료, 남은 코스 경유 안내 접근과 동작.
- [ ] 샘플 실제 목적지 요청/실패/재시도와 접힌 상태의 결과 표시.
- [ ] 현재 목적지/도착/연결 오류가 접힌 정보 안에만 숨지 않는지.
- [ ] 중복 클릭 방지와 SDK 성공 확인 후에만 후보/단계가 바뀌는지.
- [ ] 방향 전환/8초 대기/자동 앱 실행이 없고 창 배치를 사용자가 구성한 경우 이를 앱이 다시 바꾸지 않는지.
- [ ] 좁은 분할 창/넓은 창/단독 실행에서 글자와 버튼이 잘리지 않는지.

자동 반반 배치는 완료 기능이 아니다. 재개하려면 Pleos가 일반 앱에 허용하는 공식 창 배치 진입점/정책이 먼저 확인돼야 한다. 42dot 목적지 대조/지도 타일/AVD 시작 문제와 실제 추천 데이터 공급자 연결은 기존 별도 과제로 남는다.
